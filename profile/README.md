# Xext

### Extend anything. Learn something. Have fun.

**X** stands for *anything*. **Ext** stands for *extension*. Xext is a place for exploring how far we can take the things we already have, whether that means adding a feature, modifying a device, improving a process, or making a small budget go further.

We build and share these experiments for fun. Some may be practical, some may be playful, and all are opportunities to learn.

## What we extend

| Area | What that might look like |
| --- | --- |
| **Software** | Tools, integrations, plugins, and new capabilities for existing systems. |
| **Hardware** | Modifications, add-ons, repairs, and new uses for physical devices. |
| **Budgets** | Resourceful approaches that help an idea go further with the time, money, and materials available. |
| **Anything else** | Workflows, creative projects, and ideas that do not fit neatly into a category. |

## Find a project

Browse the [Xext repositories](https://github.com/orgs/xext-fun/repositories) for software, hardware work, and other experiments. Each project's repository is the best place to find its code or designs, current status, setup steps, and instructions for extending it. Check that repository's README and documentation before getting started.

There is no single setup guide for everything we do: the tools, materials, and steps depend on the project.

## Get involved

1. **Explore:** Pick a repository that interests you and read its README.
2. **Try it:** Follow the project instructions, then experiment with an extension of your own.
3. **Share what you learn:** If a repository accepts issues or pull requests, use them to suggest an idea, report a problem, improve the documentation, or contribute a change. Follow any contribution guidelines in that repository.

Please check each project's license before reusing its code or designs.

## Why we do it

We like asking, “What else could this do?” Xext is our place to find out, document the process, and make it easier for someone else to build on the result.
